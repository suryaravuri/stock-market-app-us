Improvement #6 - Entry Gate Integration
=======================================

1. Breakout confirmation is now the final entry gate.
   - Good/acceptable setup + no confirmed breakout => WAIT_FOR_BREAKOUT, actionable=false.
   - Confirmed breakout + score >= 30 + acceptable/good R:R => BREAKOUT_CONFIRMED, actionable=true.
   - POOR R:R and extended-from-support checks still block entries before breakout gating.

2. Setup response now includes breakout_confirmation so the decision is auditable.

3. Zero-volume 15-minute candles are excluded from breakout confirmation.
   - The service fetches extra candles and uses the newest 21 positive-volume candles.
   - ignored_zero_volume_candles and data_quality_note expose the data-quality handling.

4. Existing downstream risk/position/safety services automatically inherit the entry gate because they already rely on setup.actionable.

Expected PLTR behavior for the previously tested data:
- If breakout is not confirmed: action=WAIT_FOR_BREAKOUT, actionable=false.
- Position sizing should then return shares=0.
- Only BREAKOUT_CONFIRMED may set actionable=true.
